# 现场补采playbook — 问什么、先问谁、问不到怎么办

按"能不能不改结论"排序：先补齐会让**处置动作**变化的项（L1），再补会让**结论方向**变化的项（L2），
最后补文字项（L3）。同一个病例，先把时间轴与密接排完，再谈职业、疫苗、基础病。

## 0. 起报阶段（接到电话的 10 分钟）

只要有这四样就能建报告：**报告编号、标题/疾病名或"不明原因"、1 例病例的 key+分类、报告日期**。
不要等信息齐了才动手——先 `init`，再按工单补。锚点（A-identity / A-time / A-place / A-pathogen）
决定报告是 DRAFT 还是立起来了，其中 A-time 是"发病/阳性/报告/采样"四选一，最容易先拿到。

## 1. 病例（cases）—— 最小集与追问顺序

| 顺序 | 字段 | 怎么问 | 问不到 |
| --- | --- | --- | --- |
| 1 | `onsetDate` 发病日期 | "最早哪天开始不舒服"；注意发热、咳嗽、乏力分别记 | 查就诊记录/处方/购药/体温打卡/聊天记录，取最早症状日并注明推断依据 → `UNKNOWN` |
| 2 | `positiveTestDate` 阳性日期 | 要检测报告单上的采样与出结果时间，不用系统录入时间 | 实验室未回 → `PENDING` |
| 3 | `phone` 联系电话 | 本人手机；拒接补第二联系人及关系 | 学校/单位转达拿不到 → `PENDING` |
| 4 | `currentAddress.street` 街道 | 身份证地址与实际居住地不一致时两个都记 | 只到区县 → 继续追社区/网格员；`UNKNOWN` |
| 5 | `isolatedDate` 隔离日期 | "实际进隔离房间/病区"的时间，不是通知时间 | `UNKNOWN` 并写清通知时间作为旁证 |
| 6 | `exposures[]` 暴露事件 | 按天回溯：去哪、和谁、多久、戴不戴口罩；每个场景落一个 `location` | 整组拿不到是 L1，别用空数组糊过去 |
| 7 | `classification` 分类 | 疑似/临床诊断/确诊/无症状，按最新方案 | 必填，不能空 |
| 8 | `symptoms[]` | 用规范症状名，别写"感冒症状" | 空数组按缺失计 |
| 9 | `tests[]` | 每次检测一条：日期、方法、结果、Ct 值 | 未回 → `PENDING` |
| 10 | `vaccination` | 剂次、末次日期、产品 | 记不清 → `UNKNOWN`，别写"已接种"了事 |
| 11 | `travelHistory[]` | 近 14 天离开本市？去过哪 | **问过确认没有 → `NONE`**（这是 NONE 的典型用法） |
| 12 | `generation` 代次 | 由传播关系推导；关系没写就不要猜 | 留空，图上单列"代次不明" |

## 2. 密接（contacts）

先定范围再登记：**发病前 2 天起**的同住、同餐、同乘、同空间（教室/办公室/病房/车厢）。
每个密接一条：`key / relation / exposureLevel / sourceCaseKey / lastContactDate / managementStatus`。

- `exposureLevel` 枚举：密切接触者 / 次密切接触者 / 一般接触者 / 重点人群。
- 有病例却零密接，几乎必然是漏排——这是报告里最容易被追问的洞，宁可先登记再剔除。
- 判"一般接触者"要写清依据（同空间但无直接接触、全程戴口罩等）。

## 3. 场所（locations）

一个传播场景一个 `location`：`key / name / type / address / firstRelatedDate / caseKeys`。
`caseKeys` 要把涉及病例都挂上，地理分布图按场所聚合病例数。地址到街道即可成图，
只到区县时地理图会降级为"仅列病例计数"。

## 4. 传播关系（transmissionLinks）与代际

一条关系 = `id / sourceKey / targetKey / type / confidence / evidence / generationFrom / generationTo /
exposureDate / serialIntervalDays`。

- `type`：同住/同餐/同乘/同空间/医护暴露/家庭内/工作场所/其他（按台账枚举）。
- `confidence`：确诊（有流行病学+实验室支持）/ 可能（仅时间地点吻合）/ 排除。
- **`generationFrom/To` 必须写**，否则代际图判"代次不明"（上游不按拓扑猜）。
- `evidence` 写具体凭据：哪天的监控、哪次同餐、测序同源性，别写"有接触史"。

## 5. 措施（measures）

六类都要想到：隔离治疗、密接管理、核酸筛查、终末消毒、风险区划定、健康教育
（另有疫苗接种、交通管制、其他）。每条要 `startDate`；`effect`（效果/检出情况）是 L2，
定稿前必须写——没效果数据的措施等于没法证明传播被切断。

## 6. 报告头（meta / outbreak）

- `outbreak.diseaseName` 或 `pathogen` 二者之一就能立住 A-pathogen 锚点；都没有就是 DRAFT。
- `legalCategory`（甲/乙/丙类）决定报告时限，**查目录，不凭印象**。
- `detectionMode` 写清首例怎么被发现（就诊/筛查/监测/主动搜索），这决定监测灵敏度评价。
- `meta.dataSources` 每次访谈/调阅记一条（来源、类型、时间），后面写"资料来源"和溯源都靠它。
- `meta.anonymize` 默认 true，报告中姓名/idCard 应脱敏；正式报送按单位要求。

## 7. 典型"问了也不知道"的替代核实路径

| 情况 | 替代路径 |
| --- | --- |
| 记不清发病日 | 就诊/购药记录、体温打卡、请假记录、聊天记录、外卖/出行订单 |
| 不记得接触过谁 | 场所监控、门禁/消费记录、班级座位表、同乘购票记录 |
| 拒答行程 | 通信大数据（经审批）、单位考勤、社区/家属间接核实，并记录拒答事实 |
| 实验室结果未回 | 标 `PENDING` + 承诺时间，报告里写明"待回报"，不要空着 |
| 两个来源冲突 | 标 `CONFLICT`（自动抬到 L2 起），`presenceNote` 写清两个值及各自来源，回原始凭据裁定 |

## 8. 已有导出数据的清洗（大疫情网个案 CSV → 统计口径）

拿到系统导出而不是现场问答时，先清洗再统计；直接算出来的班级分布表和罹患率是错的，而且错得很像真的。

- **`单位` 字段是填卡医生自由填写，同一个班有六种以上写法**：`XX学校一（3）班`、`一(3)班`、`一3班`、
  `一年级（3）班`、`二年级（6）班`、`2（6）班`，连校名都会有错字（`刘谭实验学校`）。不归一就统计，
  同一个班被拆成四五行，最高发病班的数字直接错。
- 归一顺序：去前缀校名（凡以 `学校/小学/中学/幼儿园/实验学校` 结尾即视为校名，容忍错字）→
  半角括号转全角 → 匹配「年级+班」或「园级+班」（大/中/小/托、高一/高二）→ 输出统一形式
  `一（3）班`、`高二14班`、`大（3）班`。只剩校名或解析不出的判 `不详`，并在正文写「另有 N 例班级信息不详」。
- **中文数字与阿拉伯数字混用必须先互转**（`二6班` ↔ `2（6）班`），否则同一班两种写法各占一行。
  这套字符串函数必须单测，用真实导出的脏值做用例，不能只用自己想的规范写法。
- 事件级字段在 `突发事件信息 / 报告信息` CSV（事件 ID、级别、波及人数、首末例、经济损失分项），
  个案级在 `个案` CSV，**两者靠「事件ID」关联**。罹患率分母取自事件级的波及人数，
  不要用个案行数当分母（个案表会缺漏、会有重复卡）。
- **发病日期优先取「发病日期」，不要用「终审发病」**：终审字段常带录入时刻（`2016-05-06 10:04:37`），
  订正卡又会把它整体后移，直接当发病日会让末例莫名延后两周、结案观察期全算错。
  首末例若含订正卡，在报告里注明。
