# 感染症疫学調査報告書の作成（`outbreak-report-writing`）

[English](README.en.md) · [简体中文](README.md) · [繁體中文（台灣）](README.zh-TW.md) · [Deutsch](README.de.md) · **日本語**

現場で実際に手元にある**不完全な**情報から、その日のうちに提出できる疫学調査報告書を作る。本文は中国CDCの公文書様式に従い、欠けている項目は決して捏造せず、図表は疾患ごとに自動で揃え、Word／PDF／Markdown へいつでも書き出せる。

これは思いつきで作ったテンプレートではない。**1,300件余りの実在の疫学調査記録**（2011〜2026年の無錫市における感染症関連突発事案の全記録：江陰の腸チフス／パラチフス、宜興のコレラ、梁溪のエムポックス、輸入デング熱、血小板減少を伴う発熱症候群、さらに区県から市CDCへ提出された結案申請書）から逆算して作り上げたもの。章立ては477件の報告書で実測した順序、文体パラメータは16,815文の統計、疾患判定基準は原文に明記された観察期間と対応方針に基づく。

## 何を解決するか

| 従来の困りごと | ここでの方法 |
|---|---|
| データが揃わず報告書が書けず、三日も止まる | 欠けた項目は本文中の赤い〔待補P0-2〕になる。まず読める版を出し、付録Aが「何が足りないか、どれほど急ぐか」を示す |
| 毎回章の順序を考え直し、前回の報告書を写す | 六つの体裁ごとに固定の骨格。`stage` を選べばそのまま出力 |
| 流行曲線を折れ線で描き、階級幅を適当に決める | 潜伏期から階級幅を自動決定（ノロウイルス4〜8時間、水痘5〜7日）。初発例・最終例・介入時点を明示 |
| 大疫情網のエクスポートで同じクラスが4行に分かれる | `单位`（所属）フィールドを自動正規化。18ケースのテスト済み（校名の誤字を含む） |
| どの情報がまだ足りないか分からない | 付録AのP0が重要情報。12項目のセルフチェックで順に確認 |
| 結案報告に費用便益分析が欠けている | 第9節で国家標準の科目ごとに分類し、表をそのまま提示 |

## クイックスタート

```bash
cd ~/.hermes/skills/outbreak-report-writing
PY="env -u PYTHONPATH -u VIRTUAL_ENV vendor/venv/bin/python"

# 5項目だけでも草案が出る
$PY scripts/build_report.py --event examples/03-残缺输入/event.yaml \
    --stage initial --out ./我的输出 --formats md,docx,pdf

# 実在の症例CSVを入力にする（図4枚を自動生成）
$PY scripts/build_report.py --event examples/02-某实验学校水痘-真实个案/event.yaml \
    --stage initial --line-list examples/02-某实验学校水痘-真实个案/个案-已脱敏.csv \
    --out ./我的输出 --formats md,docx,pdf
```

`--stage`：`initial` 初回報告／`progress` 経過報告／`final` 結案報告／`closure` 結案申請書／`case` 単一症例。

例示したパスは中国語の元フォルダ名。そのまま使うこと。

## 出力：2版を同時に

既定では2ファイルが生成される。`-脱敏`（匿名化済み）が付いた方はそのまま外部に出せる。

| 項目 | 非匿名化版（内部） | 匿名化版（外部） |
|---|---|---|
| 氏名 | 张志强 | 张某（同姓で別人の場合は自動で番号付与） |
| 身分証番号／携帯／固定電話／メール | そのまま | （略） |
| 生年月日 | 2008年12月23日 | （略）、年齢は保持 |
| 住所 | 石塘湾村27号3幢2单元501室 | 石塘湾村（略）— 村・社区レベルまで保持 |
| 機関名／行政区／日付／症例数／罹患率 | 保持 | 保持 |

切り替え：`--privacy both`（既定）／`raw` は内部版のみ／`redacted` は外部版のみ。プラグイン側のパラメータは `privacy`。氏名リストは事案フィールドと症例CSVから自動収集し、本文に手書きされた身分証番号は正規表現で捕捉する。

## 二つの経路

- **軽量テンプレート**（`scripts/build_report.py`）：事案YAMLまたは大疫情網CSV → 六体裁を直接出力。単一症例、臨時対応、エクスポート表が1枚しかない場合に。
- **フルエンジン**（`scripts/flowreport.py`）：`report.json`（93フィールド／11章）→ 図4枚＋3形式＋スナップショット＋署名ゲート。十数期の経過報告を連続して作り、審査・署名フローに載せる場合に。

両経路の欠測評価は同じ判定基準の別名：L1 伝播阻止＝P0、L2 評価に影響＝P1、L3 記述の完成＝P2。

## プライバシー

本リポジトリ内のサンプルはすべて匿名化済み：氏名、身分証番号、保護者氏名、電話番号、番地を削除し、機関名は「某高級中学／某実験学校」に統一。残るのは疫学構造と統計定義のみ。原本の調査記録はリポジトリに含まれず、スキルにも同梱していない。

日本の利用者への注意：本スキルが出力する体裁は**中国CDCの公文書様式**（宋体小四・1.5倍行間、または仿宋_GB2312三号）であり、保健所の様式ではない。日本で使う場合は `templates/*.j2` の段落階層と用語を自前で調整する必要がある。

## DSHプラグイン（DeepSeek Harness）

スキルとして使うだけでなく、本リポジトリ自体がDSHプラグインパッケージになっている。導入するとエージェントに `epi_report` ツールが加わり、一言で報告書が出る。コマンドを覚える必要はない。

```bash
dsh plugin --profile web add github:naliehu/outbreak-report-writing
dsh --profile web          # 再起動後に有効。「epi_report で初回報告を出して」と伝えるだけ
```

ツールパラメータ：`action`（build／check）、`event_path`（事案YAML/JSON、必須）、`stage`（initial／progress／final／closure／case）、`line_list`（症例CSV）、`out_dir`、`formats`、`docx_profile`。

プラグインの役割は意図的に小さい：スキルディレクトリを探す → Pythonインタプリタを選ぶ → 引数を渡す → 生成物のパスを返す。報告書の書き方、図の描き方、欠測の格付けはすべて `scripts/` にあり、一度直せば両方に効く。

依存関係は段階的に縮退する：

| 導入済み | 出力できるもの |
|---|---|
| python3 + pyyaml + jinja2 | Markdown本文（図とWordは理由を明記して省略） |
| さらに matplotlib | ナラティブ図4枚と分布図3枚を追加 |
| さらに python-docx | Wordを追加。LibreOfficeがあればPDFも |

一括導入：`python3 -m pip install pyyaml jinja2 matplotlib python-docx`

設定（プロファイルの `cordis.patch.yml` に記述、すべて省略可）：

```yaml
- insert:
    - id: epi-report
      name: 'outbreak-report-writing'
      config:
        skillDir: ~/path/to/outbreak-report-writing   # 既定では自動探索
        python: /usr/bin/python3                      # 既定では vendor/venv/bin/python を優先
        outDir: ~/流调输出                             # 既定は <事案ファイルと同じ階層>/流调输出
```

## 同僚への配布

1. **丸ごとコピー**：`outbreak-report-writing/` ディレクトリ全体（`vendor/venv` 込み、約150 MB）を渡せば、`python3 scripts/build_report.py` がそのまま動く。ネットワークもpipも不要。
2. **テンプレートだけ**：`templates/*.j2` と `references/06-文风与句式库.md` を持っていき手で埋めても、規範に沿った報告書になる。このスキルの価値の半分はこの文書にある。
3. **プラグインとして導入**：`plugin/` を `~/.hermes/plugins/epi-report/` にコピーすれば、Hermesに `epi_report` ツールが加わる。
4. **疾患を追加**：`templates/disease_profiles.yaml` だけを編集。コードは触らない。

## 既知の制約

- 正式な行政区基図がないため、地理分布は会場カードか緯度経度のバブル模式図まで。GIS主題図として外部公開はできない。
- 腸チフス、デング熱、血小板減少を伴う発熱症候群、食品媒介性疾患、チクングニアの潜伏期・隔離期間はガイドライン由来でローカルコーパスではない。YAMLに `verify: true` を付けてあるので、使用前に現行の国家防控方案を確認すること。
- 世代は発症日からの推定（0.6×典型潜伏期の閾値）であり、トポロジー推論ではない。接触関係が判明している場合は伝播連鎖を優先する。
- Wordレイアウトのフォント（仿宋_GB2312）はシステムへの導入が必要。無い場合は宋体へ無言でフォールバックする。

## 言語について

スキル本体、テンプレート、生成される出力、およびそこに組み込まれた行政基準はすべて**中国語**である（中国CDCの報告書様式）。ここに置いた翻訳READMEは、中国語を解さない協力者がパッケージを評価・導入・拡張できるようにするためのものであり、ツールの出力内容を変えるものではない。
